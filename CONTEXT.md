# C# LLM Benchmark

Benchmark runner that evaluates C# solutions generated by local or remote LLMs through OpenCode and Pi coding agents using OpenAI-compatible endpoints.

## Language

**Suite**:
The kind of task being evaluated, independently of its difficulty and generator.
`greenfield` builds a new implementation; `evolution` adds a feature to a fixed,
working starter project. Existing configuration defaults to `greenfield`.
Selecting `all` executes both suites; with generator `all`, all four pairs share
one speed calibration and retain separate evaluation results.
The evolution pilot contains six scored tasks, two per difficulty: stack operations,
catalog search, reservation rescheduling, notification fallback, SQLite stock
reservations and outbox retries. Easy/medium/hard tasks are worth 10/20/30 points,
for a 120-point catalog. Four independent discovery tasks cover ordered collections,
formatter composition, HTTP batch updates and SQLite compare-exchange. Their 41 hidden
tests never enter the scored catalog. Earlier 30-point runs belong to the smaller pilot.

**Campaign**:
One invocation involving evolution, with a persisted identity, configuration, task
contracts/fingerprints, shared calibration and separate suite/generator pairs. Each
pair discovers its own temperature. `--resume-campaign` validates the original protocol,
reuses completed pairs and continues missing discovery/scored tasks. Greenfield-only
invocations and old flat folders retain their existing behavior. A complete combined
ranking requires all four full-catalog pairs, speed calibration and discovery or one
fixed temperature. The report uses the latest complete campaign per configuration
and versions, keeps missing scores unavailable, averages suites equally without
intermediate rounding, and presents old independent runs as history. See ADR-0008.

**Project delivery**:
The immutable source snapshot returned by an evolution generator, including
new sources and explicit deletions. The evaluator reconstructs it using trusted
public project files and adds hidden tests only after the generator session.
Delivery manifests include task fingerprints and source hashes; a diff records
changes from the starter. Greenfield retains its single generated-file contract.

**Regression preservation**:
The weighted fraction of existing behavior tests that still pass after a
feature change. Evolution evaluates feature and regression tests in separate
projects and multiplies their weighted pass fractions for its score. The intact
starter earns zero; compilation is a prerequisite without separate points.

**Generator**:
A solution-producing strategy selected at runtime. The benchmark supports two generators: `opencode` and `pi`. Selecting `all` runs both. All generators return a `GeneratedSolution`.
_Avoid_: Mode, backend, provider

**Agentic generator**:
A generator that spawns an autonomous coding agent in Docker with file I/O and shell access. The agent receives the task contract as natural language and produces code files through tool calls. OpenCode and Pi are both agentic generators.
Session stdout and stderr are redirected to task log files during execution.
Usage and error parsing reads one JSONL event at a time, so runner memory does
not grow with the complete session log. CommandResult carries file paths for
sessions and short output strings for installation/preparation commands.
Pi discards intermediate message/tool streaming updates before persistence by
default; `pi.full_event_log` enables full diagnostics. Pi usage counts each
final message and compaction request once in either logging setting.
_Avoid_: AI coder, coding bot

**OpenCode mode**:
Agentic generator backed by the OpenCode CLI. Runs `opencode run --format json "$prompt"` inside a Docker container and reads the generated file from the workspace.
_Avoid_: Agent mode (ambiguous)

**Pi mode**:
Agentic generator backed by the pi coding harness. Runs `pi --mode json "prompt"` inside a Docker container, producing events as JSONL on stdout and writing files via built-in tools (`write`, `edit`).
_Avoid_: Pi agent, pi harness mode

**Agentic image**:
The shared Docker image (`csharp-llm-benchmark-agentic`) used by both OpenCode and Pi generators. It provides Node.js/npm, .NET SDK, git, and ripgrep — enough for any coding agent to install its runtime and compile C# code in the workspace.
_Avoid_: Agent container, opencode image

Generator containers set `DOTNET_CLI_HOME=/tmp/benchmark-dotnet` so .NET/NuGet
initialization stays on the container filesystem. Generator configuration uses
the existing host-mounted home. This avoids first-build permission failures on
WSL Windows mounts; see ADR-0004.

Each public project's standard `bin` and `obj` directories are mounted as
container-local tmpfs with execution enabled. This lets the SDK update cache
timestamps and apphost permissions without depending on the Windows filesystem.
Source files remain in the host workspace; build outputs live only during the
container session. Both generators use this for normal and precreated containers,
including projects in subdirectories; see ADR-0006.

The evaluator's workspace tmpfs also enables executable mappings for native NuGet
dependencies such as SQLite. Its temporary directory stays noexec; the existing
network, read-only root, user, capability and resource limits still apply; see ADR-0007.

**Task contract**:
The prompt.md content of a task: natural-language instructions sent to the coding agent describing what code to produce. It becomes part of the agent's initial instruction.
_Avoid_: Task description, task spec

**Speed calibration**:
Unscored streaming inference requests made before agent execution. After a
parallel warmup, measured rounds run with configured (or optionally selected)
`generation_workers` concurrent
requests. The slowest request's output tokens per elapsed second sets a common
agent session timeout. Probe time and tokens do not enter benchmark scores or
task totals. Measurements are persisted and reused when resuming.

**Concurrency calibration**:
Optional unscored inference probes run before speed calibration, enabled with
`benchmark.calibration.concurrency_enabled` (default false). Normally the
configured `generation_workers` is used directly. With search enabled, the configured
`generation_workers` is a ceiling matching LM Studio's Max Concurrent Predictions.
Candidates start at 2 and increase by 1 through the ceiling. Each candidate is
warmed up, then measured over several rounds; the mean of the summed request
token rates selects the effective worker count. Ties favor fewer workers. A
ceiling of 1 skips selection. Discovery and both generators use the winner;
resume reuses the saved selection regardless of the search switch.

**Agent session timeout**:
The deadline for a complete Pi or OpenCode session, across tool calls. With
calibration enabled it is computed from a configurable output token budget,
measured speed, overhead and safety factor. It is not a tool iteration timeout
or a loop detector. Manual agent timeout settings apply only with calibration
disabled.
